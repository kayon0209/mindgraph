## 目标

生成不可手工修改的当前质量、性能、成本和索引基线，作为后续所有升级的对照。

## 真实业务失败

当前指标分散在历史报告和运行产物中；后续一旦调整切分或评测口径，无法证明提升来自实现而非数据或口径变化。

- `evaluation/`
- `scripts/run_ablation.py`
- `scripts/run_answer_evaluation.py`
- `src/application/evaluation_service.py`
- `src/application/index_metadata.py`
- `docs/GOLDEN_DATASET_CARD.md`

## 范围内

- 新增基线采集脚本或复用现有 Runner，输出机器可读 JSON。
- 记录 git SHA、dirty 状态、Python/SQLite、语料摘要、数据集、索引、模型和配置版本。
- 归档 retrieval/answer/ACL/conflict 的逐案结果和摘要。
- 输出失败分层，不修改任何生产路由。

## 范围外

- 不修改 Golden 标签。
- 不调 chunk/rerank/prompt。
- 不把缺失成本写成 0。

## 实施顺序

1. 获取最新 main SHA、git status 和现有基线。
2. 复现业务失败或证明当前缺口。
3. 先补失败测试与契约测试。
4. 实现最小兼容改动。
5. 运行目标测试、相关回归与必要评测。
6. 输出新旧差异、已知风险和回滚步骤。

## 测试矩阵

- 缺失必需元数据时脚本失败。
- 同一输入重复运行摘要稳定。
- dirty workspace 被显式记录。

## 验收标准

- 产出 `baseline-<date>.json` 和简短 Markdown 摘要。
- 结果可追溯到具体 SHA、dataset、corpus 和 index。
- 现有测试全绿，生产行为零变化。

## 回滚

删除新增采集脚本与产物即可；不涉及 schema 和运行时。
