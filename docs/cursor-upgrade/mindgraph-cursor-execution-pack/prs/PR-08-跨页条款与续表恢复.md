**修正 1：跨页硬切的机制已定位在源码里，改点很具体。**
`src/application/structured_chunker.py:18`：

```python
key = tuple(element.heading_path) or (f"page:{element.page_number}" if element.page_number else "root",)
```

即父块分组键 = **标题路径；无标题时退化为 `page:<页码>`，再退化为 `"root"`**。
`:19` 另有一条「累计长度 > `parent_size` 就断组」的规则。

→ **没有标题的连续条款，会在换页处被必然切断**，这就是跨页半句的机制。
修复方向应落在**分组键**或**组后合并**上，不要在切分之后再补一层正则拼字符串。

**修正 2：跨页测试需要多页 PDF，而 PDF 本体不在 git 里。**
已提交的靶标是**单页 PNG**（`rendered/*_p1..p3.png`），**验证不了跨页语义**。
可用的多页 PDF 是 `guowuyuan-gongbao-202524.pdf`（61 页）与 `ziran-ziyuan-tingsheng-guiding.pdf`（13 页），
但**两者都被 `.gitignore:69` 忽略**（本地有、换机器没有）。

→ 处理同 PR-06 修正 1：依赖 PDF 本体的测试必须在文件缺失时**明确 skip 并说明原因**。
**更建议**：把跨页恢复的确定性用例固化成**小体积纯文本 fixture 并提交进 git**
（同一逻辑文档切成连续多页元素即可，不需要真 PDF），PDF 只用于端到端验收。
否则本 PR 的回归在别人机器上永远跑不了。

**修正 3：`page_start` / `page_end` 已经算好了**（`src/application/structured_chunker.py:34`），
续表恢复可以直接复用这套页码信息，不需要新加字段。

## 目标

跨页半句、条款续页和表格续表在结构树中得到确定性恢复并可追溯到原页。

## 真实业务失败

当前 PDF 以页为主要分组，page_break 后不会自动合并语义连续内容；表格跨页可能丢表头和单位。

## 必须先阅读

- `src/infrastructure/parsers/pdf.py`
- `src/application/structured_chunker.py`
- `src/domain/models.py`
- `tests/test_document_intelligence.py`

## 范围内

- 定义跨页 join reason codes 和置信度。
- 识别页尾无终止标点、下一页小写/续句、同条款号、表头一致等信号。
- 保留 page_start/page_end 与原始 span。
- 不确定时不合并并发出 warning。

## 范围外

- 不使用 LLM 静默改写原文。
- 不删除 page boundary。
