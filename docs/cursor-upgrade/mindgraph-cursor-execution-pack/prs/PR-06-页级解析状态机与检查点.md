凡是依赖 PDF 本体的测试，必须能在文件缺失时**明确 skip 并说明原因**，不能在 CI 上伪装通过。

**修正 2：页级 parser 依赖当前未安装（`pypdf` 除外）。** `.venv` 实测缺
`fitz`(PyMuPDF) / `pdfplumber` / `pdf2image` / `pytesseract` / `paddleocr` / `rapidocr_onnxruntime` / `cv2` / `onnxruntime`；
**已有 `pypdf 6.17.0`**（可做页级文本抽取）与 `PIL 12.3.0`。
页级能力绕不开 PDF 库，先确定依赖来源并写进 `pyproject.toml`，不要靠「环境里恰好有什么」。
（逐条实测见 `05-FIELD-VERIFICATION.md` §10.2。）

**修正 3：状态机不能只覆盖 PDF，否则会立刻与 PR-04 冲突。**
`StructuredChunker` 的唯一入口是 `src/application/document_lifecycle_service.py:44`（上传路径），
而 Markdown 走 `src/document_loader.py`。新状态机若只接 PDF，Markdown 路径仍留在旧逻辑里，
PR-04 的一致性门禁随后就会报两条路径不一致。
**但注意：`document_loader.py` 现在由 PR-03 改造中（引入 `ChunkingPolicy`），动它前先确认 PR-03 已收口。**

**修正 4（最重要）：页级解析能力**已经存在**，本 PR 不是「实现页级解析」。**
实测任务书「范围内」的大部分能力**已在仓库里**：

| 任务书要求 | 现状与证据 |
|---|---|
| 页级解析 | ✅ `src/infrastructure/parsers/`：`base.py` / `registry.py` / `pdf.py` / `docx.py` / `text.py` / `xlsx.py` |
| `parser version` 记录 | ✅ `ParsedDocument.parser_version`（`src/domain/models.py:356`）；`document_lifecycle_service.py:75,82` 已组装 `diagnostics` |
| 页号可追溯 | ✅ `ParsedElement.page_number`（`:341`）；`StructuredChunk.page_start/page_end`（`:370-371`） |
| 扫描页标记 | ✅ `ParsedDocument.ocr_required_pages`（`:359`） |
| OCR 来源标记 | ✅ `ParsedElement.ocr_derived`（`:347`） |
| 表格可追溯 | ✅ `ParsedElement.table_id` / `table_rows`（`:344-345`） |

**真实缺口只有两样——这才是工作量所在：**

1. **持久化**：全仓 30 张 `CREATE TABLE` 中**没有** `ingestion_jobs` / `page_artifacts` / `document_pages`。
   页级产物解析完即随进程丢弃 → **「重试不重跑成功页」物理上做不到**（成功页没有任何落盘记录）。
2. **状态机**：无 `registered→extracting→parsed/ocr_required/failed→chunked` 的落库状态与 attempt 计数。

→ **照原文执行会重写一套已存在的解析层。** 正确改法 = 「把**已算出**的页级产物落库 + 补状态机」。

**⚠️ 本 PR 是 schema 变更**（新增表），须单独确认；验收报告须显式声明「仅新增表，未改既有表结构/列」。

## 目标

文档解析可以按页观察、重试和恢复，单页失败不丢失整份文档的诊断信息。

## 真实业务失败

当前 create_version 接收整文件 bytes 并同步解析，无法支撑大文件、断点恢复和页级故障定位。

## 必须先阅读

- `src/application/document_lifecycle_service.py`
- `src/infrastructure/parsers/base.py`
- `src/infrastructure/parsers/pdf.py`
- `src/infrastructure/database.py`
- `src/domain/models.py`

## 范围内

- 新增 additive schema：ingestion_jobs/page_artifacts 或等价结构。
- 定义 registered→extracting→parsed/ocr_required/failed→chunked 状态。
- 保存页级 checksum、parser version、诊断和 attempt。
- 先接 PDF；现有同步入口通过适配器保留。

## 范围外

- 本 PR 不接真实 OCR。
- 不迁移向量库。
- 不移除旧 parsed.json/chunks.json。

## 实施顺序

1. 获取最新 main SHA、git status 和现有基线。
2. 复现业务失败或证明当前缺口。
3. 先补失败测试与契约测试。
4. 实现最小兼容改动。
5. 运行目标测试、相关回归与必要评测。
6. 输出新旧差异、已知风险和回滚步骤。

## 测试矩阵

- 中途失败可从未完成页恢复。
- 重复提交幂等。
- 坏 PDF/空页/超限有明确状态。
- 路径与主体隔离。

## 验收标准

- 可回答失败在哪一页、哪一步、使用哪个 parser。
- 重试不重跑成功页。
- 旧上传 API 行为兼容。

## 回滚

关闭页级 pipeline flag，回到旧同步解析；新增表保留不删除。
