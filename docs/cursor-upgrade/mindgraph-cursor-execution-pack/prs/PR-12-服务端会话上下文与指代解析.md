# PR-12｜服务端会话上下文与指代解析

阶段：M3  
依赖：PR-10

## ⚠️ 现场核对修正（2026-09-11 实测）

**前提成立**：`src/application/conversation_service.py` 是**纯持久化**——
`get_messages(:139)` / `append_message(:162)` / `import_local_turns(:210)`，
**没有任何把历史回放进 prompt 的逻辑**。任务书描述准确。

**数据不缺**：`tests/test_conversations.py`（335 行）已存在，本 PR 不需要新造多轮语料。

**一处边界要在设计时定清**：`get_messages` 是 `ORDER BY sequence_no ASC` 的**全量**返回，
没有窗口或截断。本 PR 设计「最近轮次 + 摘要 + 未完成槽位」时必须明确**截断预算**
（按轮次还是按 token、超限如何处理），并按 `02-QUALITY-GATES.md` 的要求
**记录多轮上下文带来的额外输入 token 与延迟**——这是硬门禁，不是可选项。

## 目标

服务端基于 owner 隔离的最近轮次、摘要和未完成槽位解析续问，不再依赖前端拼历史。

## 真实业务失败

当前 conversation 只持久化消息；后端 Prompt 不回放历史，无法可靠理解“上一版”“那个标准”。

## 范围内

- 新增 ConversationContextService。
- 默认最近 N 轮 + 结构化摘要 + unresolved slots。

## 范围外

- 不把所有历史向量化。
- 不建立跨用户记忆。
- 不让前端成为上下文权威。
