## ⚠️ 现场核对修正（2026-09-11 第二轮实测，优先于下文）

**修正 1：ADR 引用错了。** `docs/ADR-005-m6-single-node-hardening.md` 讲的是
**单节点 profile 硬化**（MCP 协议版本协商、备份/恢复演练、SLO、威胁模型），**不是存储与队列抽象**。
而且它的「非目标」原文明确列出：**多 worker / 外部队列、K8s 部署、正式生产规模声明 —— 本轮明确不做**。

→ 本 PR 要写的是**新 ADR**（建议 `docs/ADR-006-enterprise-profile-boundaries.md`，
**该文件当前不存在，属本 PR 的交付物，不要去找**），
**不是扩写 ADR-005**。新 ADR 必须**显式说明与 ADR-005 非目标清单的关系**，否则两份 ADR 互相矛盾。
ADR-005 仍要读，但读的目的是**对齐边界**，不是「照着它改」。

**修正 2：Protocol 不是从零建，已有雏形。**
- `src/retrieval/types.py:86-115` 已有 `EmbeddingProvider` / `DenseRetriever` / `SparseRetriever`
  / `FusionStrategy` / `Reranker`；
- `src/domain/interfaces.py:6` 已有 `ChatProvider`；
- `src/infrastructure/parsers/base.py:8` 已有 `DocumentParser`。

→ 本 PR 是「**补缺 + 统一**」，不是从零建。报告里先列**已有 Protocol 清单与缺口**，
避免定义语义重叠的接口。

**修正 3：前提成立。** `src/application/task_service.py:47`
`def __init__(self, database: ProductDatabase)` —— 构造器直接吃具体类型，应用层确无抽象边界。

**修正 4：依赖链上有一环要重写。** 本 PR 依赖 PR-04 / PR-06 / **PR-09**，
而 PR-09 的任务书前提部分不成立（见 `05-FIELD-VERIFICATION.md` §6）。实际开工时点会后移。

## 目标

在不改变 Local Profile 的前提下，为对象存储、PostgreSQL、稀疏服务、分布式向量库和任务队列建立可替换边界。

## 真实业务失败

当前 SQLite/FAISS/文件系统实现被应用服务直接依赖，无法在几百 GB 或多租户场景独立扩展。

## 范围内

- 定义 DocumentStore、MetadataStore、VectorIndex、SparseIndex、TaskQueue Protocol。
- 用 adapter 包装现有 SQLite/FAISS/BM25/本地文件。
- 增加契约测试，验证替身和本地实现语义一致。
- 写 Enterprise Profile ADR 和触发阈值。

## 范围外

- 不在本 PR 接入 Milvus/Postgres/OpenSearch。
- 不让默认安装依赖外部服务。
- 不声称已支持 100GB。
